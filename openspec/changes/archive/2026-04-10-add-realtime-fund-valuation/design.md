## Context

当前 fund-manager 的基金展示依赖 `nav_history` 中的最新确认净值，因此盘中看到的值通常是 T-1，遇到节假日、QDII 或披露延迟时会退化为 T-N。仓位展示层已经具备实时市场行情接口，但基金元数据中尚未系统暴露业绩比较基准，且基金到指数的映射存在类型差异与降级需求。

本次变更只解决“展示层的盘中估算”，不改变买入、卖出、结算、净值同步或数据库结算口径。盘中估算必须与确认净值分层展示，避免把估算值误用为结算值。

## Goals / Non-Goals

**Goals:**

- 为持仓展示提供盘中实时估算净值与估算市值。
- 从晨星基金接口解析并暴露 `benchmarkName` / `benchmarkId`，为指数映射提供输入。
- 建立稳定的指数映射优先级：手工覆盖规则 > 基准名称规则 > 基金名称规则 > 不估算。
- 针对宽基指数基金、QDII 代理指数、黄金联接和无法可靠估算的基金类型定义明确的降级行为。
- 在 UI 上明确区分确认净值、估算净值和不可估算状态。

**Non-Goals:**

- 不把盘中估算值写入数据库或替代正式净值历史。
- 不改变交易结算、收益计算、导入持仓和买卖预览逻辑。
- 不在 MVP 中支持行业指数、债券指数、复合基准拆解或 beta 校准。
- 不新增外部行情提供商，继续复用现有 Morningstar 市场接口。

## Decisions

### 1. 估算值只在展示层计算，不落库

盘中估算具有瞬时性和不确定性，落库会污染确认净值语义，也会影响现有基于 `nav_history` 的收益和结算逻辑。因此估算值在命令执行时现算现用，只输出到表格或状态视图。

备选方案：把估算值单独存表。未采用，因为需要定义过期策略、查询语义和历史用途，超出本次范围。

### 2. 复用 Morningstar watch-list 作为实时指数来源

现有 `morningstar_market` 已能批量获取中国股市、全球股市和热门资产行情，并返回 `pct`、`status` 等字段。MVP 直接复用该接口以减少接入复杂度。

备选方案：新增东方财富或其他指数接口。未采用，因为当前接口已覆盖宽基、恒生科技、纳斯达克及黄金代理场景，足以支持首版。

### 3. 引入多层映射策略，而不是完全依赖 benchmarkName

晨星 `benchmarkName` 对宽基基金较有效，但对行业基金、混合基金、QDII 和商品基金存在误映射或不可直接命中的情况。因此采用以下优先级：

1. 手工覆盖规则：处理已知误映射和高价值基金，如恒生科技联接、纳指 QDII、黄金联接。
2. 基准名称规则：从 `benchmarkName` 归一化出可命中的 watch-list 指数名。
3. 基金名称规则：补充解析基金名称中的常见指数关键词。
4. 无法命中时不估算，展示明确状态。

备选方案：只靠 benchmarkName。未采用，因为已验证部分基金的 benchmarkName 与真实跟踪对象不一致，或者 watch-list 无对应指数。

### 4. 对基金类型实行显式降级，而不是宽基粗估一切

货币基金、债券基金、保守混合、行业基金和部分全球 QDII 若强行用宽基指数粗估，误差和误导风险较大。MVP 中这类基金默认不做实时估算，或只在有可靠代理映射时展示估算值。

备选方案：所有未命中的股票/混合基金都回退到沪深300。未采用，因为会输出看似精确但语义错误的结果。

### 5. UI 同时展示确认净值与实时估算，不替换原字段语义

原有“最新净值”代表确认净值，这个语义不能被盘中估算覆盖。展示层将保留确认净值，同时新增实时估算列或等价状态信息，并在休市、未映射和低置信度场景下给出显式文案。

备选方案：直接用估算值替换确认净值。未采用，因为会模糊确认值与估算值的边界。

## Risks / Trade-offs

- [映射覆盖有限] → 先保证宽基/QDII 代理/黄金场景准确，其他基金明确标记为无法可靠估算。
- [第三方 benchmarkName 误映射] → 用手工覆盖规则兜底高优先级基金，并保持人工规则优先级最高。
- [QDII 时区差异] → 对海外代理指数结果标记“仅供参考”，不将其用于结算或收益统计。
- [市场休市时展示混淆] → 使用市场 `status` 和交易时段判断回退到确认净值，并在估算列显示“休市”。
- [展示列变多降低可读性] → 先在持仓状态页优先接入，若基金列表过宽则使用紧凑文案或后续迭代再调整。

## Migration Plan

1. 先扩展基金元数据结构，解析 benchmark 字段，但保持现有命令输出不变。
2. 新增估算模块和映射规则，仅在 `status` 或基金列表执行时按需拉取行情。
3. 为可命中基金输出估算值，为不可命中基金输出降级状态。
4. 若实现效果不符合预期，可直接关闭估算展示逻辑而不影响已确认净值链路。

## Open Questions

- 未来是否需要将手工覆盖规则外置到配置文件，而不是硬编码在实现里。

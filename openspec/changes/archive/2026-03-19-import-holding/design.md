## Context

当前 fund-manager 的 `import` 命令是基于"投入金额"模式：用户提供基金名称和投入金额，系统通过查询历史净值计算出买入时的份额和手续费。

用户实际需求有两个：
1. 从其他平台（支付宝、天天基金等）导入持仓数据，这些平台导出的 CSV 通常包含"基金名称、持有金额、持有收益"
2. 在买入或卖出前，希望能够预览交易结果，了解手续费、份额变化和持仓成本均价的变化

**关键设计决策**：用户不应该关心哪些收益是导入的、哪些是买卖产生的。用户只想看到整体仓位的盈亏情况。因此，导入数据应直接写入 `transaction_log`，与后续买卖统一管理。

## Goals / Non-Goals

**Goals:**
- 支持通过 CSV 导入持仓数据（基金名称、持有金额、持有收益）
- 根据持有金额、持有收益、当前净值反推持有份额、总成本
- 导入记录以 `type='import'` 写入 `transaction_log`，与买卖统一汇总
- 支持 `--override` 覆盖模式更新已存在的导入记录
- 支持 `--merge`（默认）模式跳过已存在的导入记录
- 提供买入预览，展示手续费、获得份额、买入后持仓变化（总份额、总成本、成本均价）
- 提供卖出预览，展示赎回金额、手续费、卖出后持仓变化
- 复用现有 `fund status` 命令展示统一后的整体盈亏

**Non-Goals:**
- 不支持分红方式区分（用户已知含分红的持有收益会导致成本偏高，接受此行为）
- 不支持指定导入日期（统一使用系统当前日期）
- preview 仅做展示，不提示确认买入

## Decisions

### 决策 1：导入数据写入 `transaction_log` 而非新建表

**选择**：扩展 `transaction_log` 支持 `type='import'`

**理由**：
- 导入的持仓与后续买卖都是"份额变化"，写入同一张表便于统一汇总
- 现有 `get_holdings()` 已支持 `type IN ('buy', 'import')` 的汇总逻辑
- 用户只需看 `fund status` 就能看到整体盈亏，无需关心数据来源
- 无需新建表，简化实现

**替代方案 A**（被否决）：新建 `holdings_import` 表
- 缺点：数据分离，查询复杂，估值反而不准确
- 用户需要看两个地方，不符合"不关心来源"的需求

### 决策 2：CSV 格式

**选择**：
```
基金名称,持有金额,持有收益
中欧医疗健康混合A,11000,1000
景顺长城新兴成长,10500,500
```

**理由**：
- 用户明确表示只能导出这三列
- 无需日期列，使用系统当前日期
- 无需额外参数指定分红方式

### 决策 3：导入计算公式

**公式**：
```
当前净值 NAV = fetch_current_nav(基金代码)

持有份额 = 持有金额 ÷ NAV
总成本   = 持有金额 - 持有收益
成本价   = 总成本 ÷ 持有份额
```

**示例**：
```
持有金额 = 11000, 持有收益 = +1000, NAV = 1.1
持有份额 = 11000 / 1.1 = 10000 份
总成本   = 11000 - 1000 = 10000 元
成本价   = 10000 / 10000 = 1.0 元/份
```

**transaction_log 写入**：
- `type = 'import'`
- `shares = 持有份额`
- `money = 总成本`
- `nav = 当前净值`
- `fee = 0`
- `date = 系统当前日期`
- `status = 'settled'`

### 决策 4：Preview 命令设计

**`fund preview buy`**：
```bash
fund preview buy <基金> --money <金额>
fund preview buy <基金> --shares <份额>
fund preview buy <基金> --money <金额> --nav <净值>
fund preview buy <基金> --money <金额> --date <日期>
```

**`fund preview sell`**：
```bash
fund preview sell <基金> --shares <份额>
fund preview sell <基金> --money <金额>
fund preview sell <基金> --shares <份额> --nav <净值>
fund preview sell <基金> --shares <份额> --date <日期>
```

**参数说明**：
- `--nav`：直接指定净值，优先级最高
- `--date`：查询指定日期的最近净值，与 `--nav` 互斥
- 默认：使用当前最新净值

### 决策 5：CLI 命令汇总

```bash
# 导入持仓 CSV
fund import-holding --file holdings.csv
fund import-holding --file holdings.csv --override
fund import-holding --file holdings.csv --wallet 我的钱包

# 预览买入
fund preview buy 000312 --money 5000
fund preview buy 000312 --shares 4538.65 --date 2024-01-01

# 预览卖出
fund preview sell 000312 --shares 5000
fund preview sell 000312 --money 5500 --nav 1.1

# 查看整体持仓（复用现有命令）
fund status
fund status --wallet 我的钱包
```

## Risks / Trade-offs

**[风险] 现金分红导致成本偏高**
- 持有收益包含已发放的现金分红时，反推的总成本会比实际本金高
- → 用户已知此行为并接受，不做特殊处理

**[风险] 当前净值查询可能失败**
- 如果网络问题导致无法获取当前净值，preview 和导入流程应怎么处理
- → 必须成功获取 NAV，否则报错退出

**[风险] 成本均价计算为加权平均，非 FIFO**
- 卖出时无法区分"哪批"份额被卖
- → 接受加权平均计算，对精度要求不高

# Proposal: Automated Dividend Tracking and Enhanced Display

## Problem Statement

Currently, tracking fund dividends in `fund-manager` is a high-friction manual process. Users must manually research dividend dates and amounts, then use `fund dividend` or `fund reinvest` commands. This leads to:
1.  **Incomplete Data**: Users often forget to record dividends, leading to inaccurate "Net Cost" and ROI calculations.
2.  **Poor Visibility**: There is no dedicated view to see total dividends earned, which is a key "achievement" metric for long-term investors.
3.  **User Frustration**: Manual data entry for events that are publicly available via NAV data is tedious.

## Proposed Solution

We propose a three-pronged approach to make dividend tracking "smart" and "rewarding":

1.  **Smart Dividend Detection (Backend)**:
    *   Enhance the `sync` process to compare $NAV$ and $AccNAV$ (Accumulated NAV).
    *   A dividend is detected on date $t$ if: $(AccNAV_t - AccNAV_{t-1}) > (NAV_t - NAV_{t-1})$.
    *   The dividend per share is exactly the difference: $D = (AccNAV_t - AccNAV_{t-1}) - (NAV_t - NAV_{t-1})$.
    *   When detected, the system should either automatically record it (based on user preference) or prompt the user.

2.  **Enhanced Status Display (UI)**:
    *   Add a "Cumulative Dividend" (累计分红) column to the `fund status` and `wallet list` outputs.
    *   This provides immediate feedback on the "passive income" generated by the portfolio.

3.  **Fund-Specific Preferences (Configuration)**:
    *   Allow users to set a default dividend handling mode per fund: `Cash` (default) or `Reinvest`.
    *   This allows the "Smart Detection" to know which command (`dividend` vs `reinvest`) to trigger automatically.

## User Stories

*   **As an investor**, I want the system to automatically notice when a fund has paid out a dividend so I don't have to manually track it.
*   **As a dividend-focused investor**, I want to see exactly how much cash I've received from my holdings over time to track my passive income progress.
*   **As a user**, I want to set my preference once (e.g., "always reinvest this fund") and have the system follow that rule for all future dividends.

## Scope

*   **In-Scope**:
    *   Database schema update to store dividend preferences.
    *   Logic to detect dividends from historical NAV data.
    *   Update `status` and `wallet list` table headers and row data.
    *   A new CLI command/flag to set dividend preferences (e.g., `fund fund config <CODE> --dividend-mode reinvest`).
*   **Out-of-Scope**:
    *   Automatic tax calculation on dividends (handled as gross for now).
    *   Predicting future dividends.

## Risks & Considerations

*   **Data Quality**: If the NAV data source (EastMoney) provides inconsistent $AccNAV$, it might trigger false dividend detections. We need a sanity check (e.g., $D > 0$).
*   **Historical Backfill & Double-Counting (Critical)**: When first implemented, syncing old data might trigger a flood of dividend detections. 
    *   **The `import-holding` Conflict**: Since `import-holding` already includes historical dividends in its "Holding Profit" calculation, re-detecting those same dividends would result in double-counting and incorrectly low (or negative) net costs.
    *   **Strategy: The "Time Isolation Wall"**:
        1.  **Date-based Filtering**: The automated detection MUST ignore any dividends dated before the earliest transaction date (especially for `import` types) of a fund in a specific wallet.
        2.  **AccNAV Baseline**: When a fund is imported, the system should record the $AccNAV$ of that import date as the "baseline." Only increases in $AccNAV$ relative to this baseline will be eligible for future dividend recording.
        3.  **Human-in-the-loop**: For dividends detected within a small window (e.g., +/- 3 days) of an `import` transaction, the system should prompt for user confirmation.

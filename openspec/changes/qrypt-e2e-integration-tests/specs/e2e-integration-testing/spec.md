## ADDED Requirements

### Requirement: 自动化 E2E 挂载验证环境
系统必须提供一种机制，能够通过外部环境变量配置并在本地启动真实的 FUSE 挂载实例。

#### Scenario: 成功启动并验证挂载点
- **WHEN** 提供正确的 `QRYPT_TEST_COOKIE` 和 `QRYPT_TEST_MOUNT_POINT` 并启动测试
- **THEN** 测试程序成功启动驱动并在挂载点路径观察到文件系统就绪信号

### Requirement: 真实 POSIX 文件系统操作验证
系统必须支持在挂载点上直接执行标准的文件系统调用（创建、读取、更新、删除），并验证其一致性。

#### Scenario: 跨加密层的内容校验
- **WHEN** 在挂载点写入一个加密文件，卸载并重新挂载后再次读取
- **THEN** 读取的内容必须与原始写入数据完全一致（验证加解密与缓存落库逻辑）

### Requirement: 异步同步状态确定性反馈
系统必须暴露一种机制，允许测试代码在不修改业务代码的前提下，确认异步上传任务是否已真正完成。

#### Scenario: 同步完成轮询
- **WHEN** 写入文件后轮询该路径对应节点的 `isDirty` 状态
- **THEN** 当 `isDirty` 变为 `false` 时，意味着远程 API 已成功完成上传并返回有效 FID

## Context

当前分支 `vk/dd59-wallet-del` 已经实现了钱包删除的基础逻辑，但存在以下问题：
1. **本地化不完整**：所有新增的 CLI 文档和提示语均为英文。
2. **逻辑健壮性**：如果删除了当前正在使用的活跃钱包，系统可能会处于“选中了一个不存在的 ID”的异常状态。
3. **代码规范**：部分地方使用了 `expect` 进行错误处理，且缺乏自动化测试验证。

## Goals / Non-Goals

**Goals:**
- 将 `wallet delete`（及别名 `del`）命令及其所有交互消息完全本地化为中文。
- 确保删除当前活跃钱包时，自动从 `app_config` 中清除相关配置。
- 为钱包删除逻辑添加单元测试和集成测试，确保级联删除有效且状态一致。
- 提升错误处理的优雅程度，使用 `Result` 替换 `expect`。

**Non-Goals:**
- 不涉及数据库 Schema 的结构性变更（现有 Schema 已支持 `ON DELETE CASCADE`）。
- 不支持一次性批量删除多个钱包。

## Decisions

1. **命名对齐**：子命令命名为 `Delete`，并设置 `alias = "del"`。这既满足了用户对 `del` 的需求，又保持了与 `fund fund delete` 命令在命名风格上的一致性。
2. **数据库层封装**：在 `db.rs` 中提供统一的 `delete_wallet(conn, wallet_id)` 函数。
   - **理由**：该函数不仅负责执行 SQL 删除语句，还负责检查并清理 `app_config`。将此逻辑封装在 DB 层可以确保无论通过何种途径（CLI 或其他功能）删除钱包，状态都能保持一致。
3. **交互确认复用**：直接复用 `main.rs` 中的 `confirm_action` 辅助函数。
   - **理由**：该函数已成熟支持 `-y/--yes` 全局参数。
4. **按 ID 删除而非名称**：虽然 CLI 输入的是名称，但在 `main.rs` 的路由逻辑中先通过名称查出 ID，再调用 `delete_wallet(id)`。
   - **理由**：ID 是主键，操作更精确。如果找不到 ID，可以在路由层直接报错。

## Risks / Trade-offs

- **[风险] 误删数据** → **[缓解]** 强制交互确认，并在提示语中明确列出钱包名称。
- **[风险] 活跃钱包失效** → **[缓解]** 在删除逻辑中加入显式的 `app_config` 检查与清理机制。
- **[风险] 级联删除范围过大** → **[缓解]** 这是预期的行为（删除钱包即删除其投资组合），通过文档和提示语告知用户。

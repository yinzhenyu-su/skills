# Qrypt 需求规格说明书 (Requirements Specification)

Qrypt 是一个跨平台的夸克网盘 (Quark Drive) 挂载工具，旨在通过 FUSE 接口提供与本地文件系统一致的操作体验，同时完全兼容 rclone crypt 的加密逻辑。

## 1. 平台支持与环境要求

### 1.1 支持的操作系统

- **macOS**：
  - 支持 macOS 12 (Monterey) 及更高版本（Intel 与 Apple Silicon 架构均支持）。
  - **核心依赖**：必须安装 [macFUSE](https://macfuse.github.io/) (4.0+)。
  - **系统特性适配**：针对 Finder 的元数据处理、虚拟回收站及 xattr 进行了专项优化。
- **Linux**：
  - 支持主流发行版（如 Ubuntu, Debian, CentOS, RHEL, Arch Linux 等）。
  - **核心依赖**：依赖 `libfuse` 或 `fuse3`。
  - **权限要求**：运行用户必须拥有 `/dev/fuse` 的访问权限（通常需加入 `fuse` 用户组）。

### 1.2 文件系统挂载 (FUSE)

- **挂载点管理**：将夸克网盘指定路径（`root_path`）挂载到本地目录。
- **Finder/文件管理器集成**：
  - 在 macOS Finder 中显示为网络磁盘，卷标为 `QuarkDrive`。
  - **虚拟回收站 (Virtual Trash)**：拦截并模拟 `.Trash` 和 `.Trashes` 的查询请求，返回虚拟的 Stat 信息，防止系统在云端尝试创建不存在的回收站目录。
- **用户身份模拟**：自动获取当前进程的 UID/GID，确保本地权限校验通过。

### 1.3 rclone 兼容加密协议

- **核心逻辑参考**：加密实现严格对齐 rclone crypt 后端规格。
  - **参考源码**：[rclone/backend/crypt/cipher.go](https://github.com/rclone/rclone/blob/master/backend/crypt/cipher.go)
- **密钥派生**：基于 scrypt (N=16384, r=8, p=1) 从密码和盐值派生 80 字节密钥。
- **文件名加密**：
  - 采用 PKCS7 填充、EME-AES 模式。
  - 使用 **Lowercase Base32** 编码，实现与 rclone crypt 兼容。
- **内容加密 (NaCl SecretBox)**：
  - 采用 XSalsa20-Poly1305 分块加密。
  - **分块结构**：`64KB (明文) -> 16B (MAC) + 64KB (密文)`。
  - **Nonce 管理**：每文件包含 24 字节 File Nonce，块 Nonce 由 File Nonce 与块索引累加生成。
- **文件头**：首部包含 `RCLONE\x00\x00` (8B) + File Nonce (24B)。

### 1.3 夸克网盘驱动技术规格 (Quark Driver)

- **核心行为参考**：本项目的驱动行为（如接口选择、签名算法、秒传逻辑）深度对齐 AList 夸克 PC 驱动实现。
  - **参考源码**：[alist-org/alist/drivers/quark_uc](https://github.com/AlistGo/alist/blob/main/drivers/quark_uc/driver.go)
- **API 韧性与多基地址回退**：
  - 驱动必须支持基地址冗余（如 `QuarkBaseURL`, `QuarkV2URL`）。
  - 管理接口（Delete/Rename/Move）在遇到 404/405 或 DNS 错误时，必须执行基地址自动轮询。
- **身份认证与续期**：支持 Cookie 鉴权，并必须能够拦截 API 响应自动更新内存中的 `__puus` 凭证，确保长效会话不中断。
- **并行元数据抓取**：对于文件数超过单页（100）的目录，必须采用并行协程同步抓取后续页码，以提升 `ListFiles` 响应速度。
- **定制化 OSS 授权协议**：
  - **签名对齐**：`auth_meta` 构建必须严格遵循夸克服务端要求的字段顺序。
  - **特征头部**：必须显式携带 `x-oss-user-agent` (aliyun-sdk-js 兼容版本) 头部，否则会导致 OSS 校验失败。
- **哈希上报与秒传 (Dedup)**：支持通过 `/file/update/hash` 链路实现上传闭环，并在秒传成功时执行 Fid 一致性二次校验。
- **下载链路优化**：实现 `urlCache`，对获取到的 OSS 下载地址设置 10 分钟缓存，避免重复调用 API。

## 2. 数据同步与一致性需求

### 2.1 写入一致性与路径原子性

- **上传前清理 (Delete-before-upload)**：由于加密文件名包含随机 Nonce，上传前必须按“解密后的明文名”查找并删除远程已存在的同名文件，防止产生 `(1)` 冲突副本。
- **秒传验证 (Dedup Verification)**：如果 `UploadPre` 返回秒传成功，必须验证该 Fid 对应的明文文件名是否与当前请求一致。若不一致（Hash 碰撞或陈旧 Fid），必须删除该 Fid 并强制重新上传。
- **路径变更原子性 (Path Atomicity)**：目录重命名或移动必须保证原子性。系统通过 `ops_log` 记录事务状态，确保在操作中途崩溃时，重启后能恢复到“完全移动”或“完全回滚”的状态，避免路径碎片化。
- **孤儿节点防御 (Orphan Prevention)**：当父目录被删除时，系统必须拦截并协调该目录下正在进行的上传任务，确保不会在云端产生无父级引用的“孤儿 Fid”。

### 2.2 任务编排与可靠性

- **操作日志 (Journaling)**：元数据操作前记录 `ops_log` 到 SQLite，支持启动时自愈重试。
- **同步锁机制**：基于文件唯一身份标识加锁，确保同一文件在重命名或重试期间任务不重叠。
- **写回策略 (Write-back)**：文件写入先进入本地 `pending` 状态，`flush/release` 时异步触发上传。

### 2.3 元数据完整性与校验

- **加密大小精确映射 (Size Mapping)**：由于加密分块存在固定 Overhead（64KB 增加 16B MAC + 32B Header），系统必须能够根据明文大小精确计算预期的密文大小。同步完成后，必须执行双向校验，确保云端存储长度与本地逻辑一致。
- **时间戳补偿 (Timestamp Compensation)**：在云端 API 不支持自定义 `mtime` 的情况下，系统需在本地 SQLite 中持久化维护文件的原始修改时间。在 VFS 视图中，应优先返回本地记录的时间戳，而非云端的 `upload_at` 时间，以保证 `make` 等构建工具的正确性。

### 2.4 冲突处理与自愈

- **写后读一致性 (Read-After-Write)**：对于处于 `pending` 或正在同步的文件，`Stat` 和 `Read` 操作必须始终指向本地暂存区（Staging）中的最新数据。
- **远程冲突解决**：当检测到本地正在修改的文件在云端已被其他客户端更改（Fid 或 Hash 不一致）时，系统需根据配置执行“本地覆盖”或“保留冲突副本（.conflict）”策略。
- **异常残留清理**：系统应定期扫描并自动清理云端超时的分段上传任务（UploadID）以及本地过期的孤儿暂存文件，防止存储空间浪费。
- **元数据对账 (Reconciliation)**：提供自愈机制，支持定期对比本地 SQLite 缓存树与云端实际 Fid 树，发现并修正因 API 偶发超时或网络波动导致的节点状态不一致。

## 3. 性能与 UX 优化需求

### 3.1 分级并发控制 (Tiered Concurrency)

- 为防止大规模操作导致 FUSE 线程锁死，系统必须使用三级信号量隔离：
  - **Meta (500)**：用于 `ListFiles`, `Sort` 等元数据读取。
  - **Mgmt (500)**：用于 `Delete`, `Rename`, `Move` 等批量管理。
  - **General (200)**：用于常规 API 请求。

### 3.2 缓存策略与性能优化

- **元数据缓存 (TTL)**：默认 60s 缓存目录列表，减少重复的 `ListFiles` 请求。
- **负缓存 (Negative Caching)**：
  - **核心需求**：必须记录并缓存“文件不存在 (ENOENT)”的结果。
  - **必要性**：拦截操作系统（如 macOS Finder）对 `.DS_Store`、`._*` 等文件的频繁扫描，消除因反复 404 网络请求导致的界面假死。
  - **实现逻辑**：将 `parentFid:name` 作为键值，缓存失效时间（TTL）。下次请求时若命中且未过期，立即返回错误而不发起网络调用。
  - **一致性要求**：当在该目录下成功创建文件时，必须立即清除对应的负缓存条目，确保新文件可见性。
- **URL 缓存**：对 OSS 下载链接设置 10 分钟缓存，支持 HTTP Range 分块读取，优化大文件流式读取性能。
- **读取预加载**：根据顺序读取模式自动触发分块预取。
- **目录元数据预取 (Directory Metadata Prefetching)**：
  - **核心需求**：当用户打开并访问某一目录（`Opendir/Readdir`）时，系统应在返回当前结果后，自动触发对该目录下所有子目录的元数据预取。
  - **优化目标**：通过提前填充缓存，消除用户进入子目录时的网络延迟，实现层级导航的“秒开”体验。
  - **深度控制**：默认仅预取当前访问目录下的一级子目录内容，避免递归过深导致 API 请求过载。
  - **并发与限流**：预取任务必须在后台异步执行，不得阻塞当前的 FUSE 请求，且需严格受 `MetaSemaphore` 信号量限制。

### 3.3 macOS 特化兼容性

- **xattr 抑制**：静默忽略 `Setxattr`, `Getxattr`, `Removexattr` 等操作并返回成功/ENOATTR，防止 macOS 系统属性写入失败导致的 `Operation not permitted`。
- **Mknod 转发**：透明将 `Mknod` 请求转发至 `Create` 处理。
- **挂载标志**：默认启用 `noappledouble`, `defer_permissions`, `iosize=1MB`。

## 4. 配置管理与命令行需求

### 4.1 配置文件规格 (TOML)

- **多级自动化搜索**：启动时若未通过 `-f` 显式指定路径，系统必须按以下优先级顺序自动检索配置文件：`./qrypt.toml` -> `~/.config/qrypt/qrypt.toml` -> `~/.qrypt.toml` -> `/etc/qrypt/qrypt.toml`。
- **配置模板 (Template)**：系统生成的 `qrypt.toml` 必须包含以下结构：

```toml
[quark]
# 夸克网盘 Cookie（必填）
cookie = "your_cookie_here"
# 挂载的网盘子路径（默认 "/" 根目录）
root_path = "/Test"

[encryption]
# 加密密码（必填，需与 rclone crypt 一致）
password = "your_password"
# 加密盐值（可选，rclone 默认为空）
salt = ""

[cache]
# 本地缓存目录（存储分块数据与 SQLite 元数据）
dir = "~/.qrypt/cache"
# 元数据数据库文件名
db_name = "qrypt_cache.db"
# 最大磁盘缓存占用 (支持 KB, MB, GB, TB)
max_size = "10GB"

[mount]
# 本地挂载点路径
point = "~/QryptMount"
# 允许其他用户访问挂载点（通常需要 root 权限及 /etc/fuse.conf 配置）
allow_other = false

[sync]
# 后台并发上传文件数
concurrent_uploads = 3
# 目录列表缓存有效期 (支持 s, m, h)
dir_cache_ttl = "60s"
# 负缓存 (Negative Cache) 有效期
neg_cache_ttl = "30s"

[log]
# 日志级别: debug, info, warn, error
level = "info"
# 日志文件路径（留空则输出到标准错误输出）
file = "~/.qrypt/qrypt.log"
```

- **动态更新**：系统在运行过程中检测到 `__puus` Cookie 变更时，应当能够同步更新内存中的配置状态。

### 4.2 命令行交互与参数规格

- **参数覆盖优先级 (Precedence)**：
  - **最高**：命令行参数 (Flags) > 配置文件 > 系统默认值。
- **全局参数与子命令**：
  - `qrypt init`：
    - 功能：在当前目录生成默认 `qrypt.toml`。
  - `qrypt mount [flags]`：核心挂载子命令，支持以下关键参数：
| 参数 | 缩写 | 功能描述 | 默认值 |
| :--- | :--- | :--- | :--- |
| `--config` | `-f` | 指定配置文件路径 | 自动搜索 (./, ~/.config/ 等) |
| `--cookie` | `-c` | 覆盖夸克网盘 Cookie | 配置文件对应项 |
| `--password` | `-p` | 覆盖 rclone 加密密码 | 配置文件对应项 |
| `--salt` | `-s` | 覆盖 rclone 加密盐值 | 空 (Default Salt) |
| `--root-path` | `-r` | 指定网盘内的挂载起点路径 | `/` |
| `--mount` | `-m` | 指定本地挂载点路径 | 配置文件对应项 |
| `--cache` | `-a` | 指定本地分块与元数据缓存目录 | `~/.qrypt/cache` |
| `--allow-other`| - | 允许其他用户访问挂载点 (需系统权限) | `false` |
| `--log-level` | - | 日志级别 (debug, info, warn, error) | `info` |

- **交互友好性**：
  - **Usage Hints**：当必填参数（如 cookie 或 password）缺失时，程序必须打印明确的错误信息并显示相应的 Help 示例。
  - **优雅退出**：挂载进程必须捕获 `SIGINT` (Ctrl+C)，在退出前完成所有 `pending` 节点的写入尝试并调用 FUSE 的卸载接口。

## 5. 用户操作场景与预期行为

### 5.1 复杂目录结构上传 (如 dist 文件夹)

- **操作**：用户将一个包含多层子目录和大量小文件的文件夹（如前端构建输出 `dist`）拖入或通过 `cp -r` 拷贝至挂载点。
- **预期预期**：
  - **结构完整性**：所有层级的文件夹必须在网盘中正确递归创建。
  - **内容加密**：每一个文件的文件名和内容均已根据 rclone 标准进行加密，且在网盘网页端不可直视明文。
  - **并发处理**：系统应根据 `concurrent_uploads` 配置并发启动多个上传任务，确保大量小文件能快速同步。
  - **零丢失**：即使复制过程中发生网络抖动，系统也应通过后台 `pending` 机制最终完成所有文件的同步。

### 5.2 大文件写入与读取

- **操作**：用户拷贝一个数 GB 的视频文件或安装包。
- **预期行为**：
  - **写回平滑**：写入过程不应因等待网络而卡顿，数据应首先进入本地暂存区。
  - **自动分段**：对于大文件，系统必须自动触发 Multipart Upload，并实时上报分段哈希。
  - **读取即点即播**：支持随机读取（Random Access），播放器拖动进度条时，系统应能快速定位并下载对应的分块数据进行解密。

### 5.3 跨设备一致性

- **操作**：用户在设备 A 上通过 Qrypt 删除了一个文件，然后在设备 B 上刷新目录。
- **预期行为**：
  - 设备 B 在元数据 TTL 过期后或强制刷新时，该文件必须消失，且不留任何孤儿节点。

### 5.4 异常中断恢复

- **操作**：用户在文件复制进行到一半时强制关闭电脑或程序崩溃。
- **预期行为**：
  - **自愈**：下次启动 Qrypt 时，系统应自动扫描 `ops_log` 和暂存目录，对未完成的任务进行断点续传或重试，确保数据不会处于中间损坏状态。

### 5.5 文件夹递归删除 (Recursive Delete)

- **操作**：用户执行 `rm -rf` 或在 Finder 中清空包含大量内容的文件夹。
- **预期行为**：
  - **即时反馈**：文件夹及其内容应立即从本地 VFS 视图中消失。
  - **后台清理**：系统在后台调用夸克管理接口（Delete）执行清理。如果子项过多，必须利用 `MgmtSemaphore` 并发处理以提高效率。
  - **状态闭环**：成功删除后，必须彻底清除本地 SQLite 中对应的 Fid 记录及文件暂存，确保无残留。

### 5.6 文件夹重命名与移动 (Rename/Move)

- **操作**：用户对文件夹进行重命名或跨目录拖拽移动。
- **预期行为**：
  - **路径原子性**：VFS 视图立即更新。
  - **同步协调**：如果重命名时文件夹内有文件正在同步，系统必须确保同步任务完成后，文件最终出现在正确的新路径下，且网盘端不产生重复副本。

### 5.7 空文件夹管理

- **操作**：用户创建一个不含任何文件的空文件夹。
- **预期行为**：
  - **显式持久化**：夸克网盘支持空文件夹 Fid，系统必须显式发起 API 请求创建，确保该空文件夹在其他设备上可见，而非仅通过文件路径模拟。

### 5.8 弱网与离线操作

- **操作**：在网络极其不稳定或暂时离线时执行元数据操作（如删除、新建目录）。
- **预期行为**：
  - **操作入库 (Journaling)**：系统不应报错卡死，而是将操作记录到 `ops_log` 挂起。
  - **自动回放**：网络恢复后，系统应自动按顺序回放挂起的操作，实现云端与本地的最终一致性。

### 5.9 对未完成同步内容的操作 (Concurrent Operations on Pending Content)

- **场景**：用户对一个处于“脏状态（Dirty）”或“正在同步（Syncing）”的文件或目录执行操作。
- **预期行为**：
  - **查 (Read)**：**写后读一致性**。系统必须始终返回本地暂存区（Staging）中的最新数据版本，即使该版本尚未同步至云端。
  - **改 (Update/Write)**：**链式同步**。如果在上传过程中文件再次被写入，系统必须确保当前上传块的完整性（通过快照或锁），并在当前同步完成后自动排队发起新一轮同步，确保云端最终版本正确。
  - **删 (Delete)**：**删除绝对优先**。本地视图立即移除。系统应尝试撤回正在进行的上传任务；若上传已进入终态，系统必须在上传完成后补发删除请求，防止文件在云端“复活”。
  - **重命名/移动 (Rename/Move)**：**身份绑定同步**。由于同步基于 Fid 而非路径，重命名操作不应中断同步。最终上报云端的元数据必须反映最新的路径和名称。

## 6. 安全、隐私与资源约束

### 6.1 隐私保护与日志脱敏

- **敏感数据屏蔽**：系统日志必须严格脱敏。禁止在任何日志输出中包含：
  - 夸克 Cookie 及 `__puus` 令牌。
  - rclone 解密密码及盐值。
  - OSS 上传/下载的 AuthKey 或签名 URL。
- **本地权限隔离**：缓存目录（Cache）和暂存目录（Staging）的权限应限制为仅当前运行用户可读写（0700），防止本地其他非特权用户读取暂存的明文数据。

### 6.2 资源管理与配额约束

- **本地空间预警 (ENOSPC)**：在写入文件到暂存区前，系统必须评估本地磁盘剩余空间。若剩余空间不足以容纳当前文件，应直接返回 `ENOSPC` 错误。
- **内存脚印控制**：
  - 元数据节点（Node）应支持按需加载或在极大规模目录下具备 LRU 清理机制。
  - 并发上传请求的信号量必须与系统内存容量相匹配，防止并发过高导致内存溢出。
- **句柄泄露防护**：系统必须确保所有打开的本地暂存文件句柄在同步完成后或 VFS `Release` 时被正确关闭。

## 7. 故障排除与调试需求

- **日志追踪**：详细记录 FUSE 调用、OSS 交互与 API 状态码。
- **性能埋点**：支持记录关键步骤（如加密、上传、哈希校验）的耗时，便于性能调优。
- **优雅退出**：接收中断信号后，确保所有 `pending` 状态的 VFS 节点能够安全卸载，防止挂载点残留。

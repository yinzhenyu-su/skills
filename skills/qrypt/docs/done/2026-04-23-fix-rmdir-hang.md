# 变更方案：修复删除大目录（如 dist）导致的程序卡死

## 问题背景
用户在执行 `rm -rf dist` 删除包含大量文件的目录时，发现 `qrypt` 会出现程序卡死甚至挂载崩溃的情况。尤其是在删除的同时触发目录刷新（如 Finder 自动刷新或背景预取）时，问题更加明显。

## 根因分析
1. **驱动信号量瓶颈**：`QuarkDriver` 的 `mgmtSem` 和 `metaSem` 信号量上限较低（100），在 `rm -rf` 产生大量并发 `Unlink` 请求时，信号量迅速耗尽，导致后续所有元数据请求（如 `lookup`）阻塞，最终引发 FUSE 超时。
2. **Rmdir 锁竞争**：`Rmdir` 在检查目录是否为空时，长时间持有父目录锁并遍历子节点。这与背景刷新线程（`MergeRemoteChanges`）产生了严重的锁争用，导致 FUSE 线程响应延迟。
3. **刷新风暴**：多个并发请求（Readdir/Prefetch）可能同时触发同一个目录的 `MergeRemoteChanges`。在没有去重机制的情况下，大量的网络请求和复杂的合并逻辑并行执行，造成 CPU 和网络 IO 负载过高。

## 解决方案
1. **信号量扩容**：将 `mgmtSem` 和 `metaSem` 从 100 增加到 500，提升应对瞬时并发请求的处理能力。
2. **Merge 操作去重（Gating）**：在 `QryptFS` 中新增 `merging` 映射，通过 channel 机制确保同一个 FID 在同一时间只有一个协程在执行 `MergeRemoteChanges`。后续并发请求会静默等待第一个完成后直接返回。
3. **Rmdir 逻辑优化**：
    - 在检查 `isEmpty` 前先获取子节点快照，缩短持有父目录锁的时间。
    - 在检查逻辑中加入对“路径保护”和“墓碑状态”的判断，过滤掉已经在删除流程中的子项。
4. **延迟保护回退**：在 `MergeRemoteChanges` 中保留了基于时间的保护（30秒）作为兜底，确保在 API 索引延迟时不会误删刚同步的文件。

## 影响评估
- **性能**：由于引入了 Merge 去重，高并发下的 CPU 占用将显著降低。
- **稳定性**：显著提升了大文件操作场景下的挂载稳定性，减少了 FUSE 驱动无响应（Hang）的风险。

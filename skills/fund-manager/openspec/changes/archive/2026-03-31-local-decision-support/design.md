## Context

`fund-manager` 当前已经具备了基础的交易记录和赎回费率阶梯存储。本设计旨在这些数据之上，通过简单的本地数学逻辑，为用户提供盈亏平衡点、持有期优化和收益目标提醒。

## Goals / Non-Goals

**Goals:**
- 实现自动化的持有期跳档检测，并量化节省的金额。
- 计算保本净值，帮助用户判断卖出是否“回本”。
- 提供轻量级的收益率报警（止盈/止损）。
- 在不破坏现有 CLI 布局的前提下，通过符号和底部提示进行展示。

**Non-Goals:**
- 不引入外部指数估值 API（属于第三阶段）。
- 不实现逐笔（Lot-level）成本追踪（依然使用当前的加权平均成本）。
- 不自动执行买卖操作。

## Decisions

### 决策 1：保本净值计算公式
**选择**：`NAV_breakeven = TotalCost / (TotalShares * (1 - r))`，其中 `r` 是当前持有天数对应的赎回费率。
**理由**：该公式计算的是“卖出后到手金额刚好等于持仓成本”时的实时净值，对用户判断回本最具参考意义。

### 决策 2：阶梯跳档检测逻辑
**选择**：
1. 查找当前基金的所有 `redemption_fee_tiers`。
2. 找到最小的 `min_days > current_holding_days` 的档位。
3. 若 `min_days - current_holding_days <= 7`（阈值可配置，暂定 7 天），则触发提醒。
**理由**：7 天是一个合理的观察窗口，通常覆盖了基金交易的主要周期。

### 决策 3：止盈止损配置存储
**选择**：在 `fund` 表中新增 `target_profit_rate` 和 `stop_loss_rate` 两个 `TEXT` 字段（存储 Decimal）。
**理由**：这些配置是基金级别的属性。虽然可以放在 `app_config`，但直接在 `fund` 表中查询更高效，且方便未来扩展。

### 决策 4：展示逻辑集成
**选择**：
- `status` 命令：新增“保本净值”和“决策提醒（符号）”列。
- `preview sell` 命令：在最后增加一个“💡 建议” Block。
- 汇总提示：在 `status` 表格底部显示详细的文字建议。
**理由**：符号能快速吸引注意力，文字建议能提供具体的操作指引。

## Risks / Trade-offs

- **[Risk]** 加权平均成本可能与实际先进先出的计税逻辑有细微偏差。
  - **Mitigation**: 在计算建议时标注“估算值”，提醒用户以基金公司最终确认为准。
- **[Risk]** 列数增加可能导致小屏幕终端换行。
  - **Mitigation**: 精简列名，或在未来支持 `--compact` 模式。

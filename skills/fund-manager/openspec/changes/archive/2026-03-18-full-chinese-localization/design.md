## Context

目前 `fund-manager` 的所有 UI 字符串（帮助信息、表头、日志）都硬编码在各模块的 Rust 源文件中。为了实现汉化，需要对这些字符串进行系统性的替换。由于本项目是一个垂直领域的工具，且目标用户明确，目前不采用复杂的多语言 i18n 框架（如 `gettext` 或 `fluent`），而是直接将源码中的字符串常量替换为中文。

## Goals / Non-Goals

**Goals:**
- 实现 CLI 界面 100% 中文化。
- 统一金融术语的中文表达。
- 确保表格在中文表头下的视觉对齐。
- 更新自动化测试以通过中文断言。

**Non-Goals:**
- 不引入外部 i18n 库或 `.po`/`.yaml` 翻译文件（维持源码直接修改，追求简洁）。
- 不汉化底层数据库表名或字段名（仅汉化展示层）。
- 不改变现有的英文命令（如 `buy`, `status`）以保持 CLI 快捷性。

## Decisions

### 1. 术语对应表
为了保证全系统一致性，制定以下术语映射：
- `Shares` -> `持仓份额`
- `Cost` -> `持仓成本`
- `NAV` -> `当前净值`
- `Valuation` -> `当前市值`
- `P&L` -> `盈亏额`
- `P&L %` -> `收益率`
- `Wallet` -> `钱包`
- `Fund` -> `基金`

### 2. CLI 元数据翻译
在 `cli.rs` 中，利用 `clap` 的属性宏将所有 `about` 和 `long_about` 字段替换。对于参数名（如 `--money`），保持参数名不变，但修改其 `help` 描述。

### 3. 表格渲染适配
`comfy-table` 在处理中文字符宽度时，如果出现偏移，需检查终端环境对全角字符的支持。设计上将表头统一为等长或合理的比例，尽量避免在表格中使用过长的中文词汇。

### 4. 测试用例重构
由于 `tests/cli_tests.rs` 依赖于对标准输出的字符串匹配，汉化后这些测试会失效。设计上需要同步更新测试中的 `contains` 断言。

## Risks / Trade-offs

- **[Risk] 字符编码/对齐问题**：不同终端对中文字符宽度的渲染不一可能导致表格错位。
  - **Mitigation**：优先使用标准中文字符，并在主流终端（如 iTerm2, VSCode Terminal）验证。
- **[Trade-off] 缺乏多语言灵活性**：直接修改源码字符串意味着如果未来想切回英文，需要再次修改源码。
  - **Rationale**：鉴于该工具主要面向中文理财用户，该成本可控且能换取更快的开发速度。

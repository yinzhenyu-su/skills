## MODIFIED Requirements

### Requirement: 本地模糊/精准匹配优先
系统在处理基金代码或名称输入时，必须首先查询本地数据库的 `fund` 表，支持精确代码、精确名称以及模糊名称查询。

#### Scenario: 本地精准命中
- **WHEN** 用户输入 "020988" 或 "南方恒生科技" 且本地已存在记录
- **THEN** 系统直接使用本地缓存，不发起搜索请求

#### Scenario: 本地模糊匹配
- **WHEN** 用户输入 "富国高端" 且本地存在唯一的 "富国高端制造行业股票A (000513)"
- **THEN** 系统 SHALL 自动识别并使用该基金，不再进行远程搜索

### Requirement: 模糊搜索返回多个结果时的选择策略
当本地或远程接口返回多个结果（如 "020988", "020989"）时，系统必须根据 `interactive` 标志决定处理方式：在交互模式下提供选择列表，在非交互模式下直接返回错误。

#### Scenario: 交互模式下多个结果
- **WHEN** 用户在交互模式下输入 "南方" 且发现多个结果（无论是本地还是远程）
- **THEN** 系统必须通过 CLI 展示一个交互式列表供用户选择，直到用户确认或退出

#### Scenario: 非交互模式下多个结果
- **WHEN** 用户在非交互模式下输入 "南方" 且发现多个结果
- **THEN** 系统不得展示交互式列表，必须直接返回明确指出匹配冲突的错误信息
